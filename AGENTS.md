## 1. What this project is

Two products in one repo:

1. **The keyboard** — a 2 × 32 key split low-profile ergonomic keyboard ("SweepyWay v0.2"),
   meant to be physically built and used by the author.
2. **The pipeline** — a declarative, end-to-end keyboard factory: one YAML in, PCB + plate +
   case + palm rest + tenting + fabrication data + previews out, with no manual CAD work.

When you change something, ask which of the two you are serving. A change that makes the
keyboard better but hardcodes assumptions into the pipeline is usually wrong; the pipeline is
expected to eventually become configurable by non-CLI users (see `docs/ROADMAP.md`).

## 2. Golden rules

1. **`ergogen/config.yaml` is the only source of truth for geometry.** Never hand-edit
   `ergogen/output/**` (regenerated), `filtered-output/**` (produced by CI and downloaded),
   or `*.kicad_pcb` files. If something is wrong in an output, fix the config or a footprint.
2. **`ergogen/footprints/ceoloide/` is a git submodule** (the author's fork). Changes there
   must be committed *and pushed to `origin` on branch `feature/sweepyway-customizations`*
   before you bump the pointer in the parent repo, otherwise CI cannot check it out. The
   author has been burned by this: see `plans/fix-submodule-connection-issue.md`.
3. **Verify by regenerating.** Any config/footprint edit must be followed by
   `./scripts/regen.sh` + `./scripts/check_matrix.py`. Both must pass.
4. **Never claim a board is manufacturable without checking copper.** The published CI output
   has shipped unrouted gerbers before (see `docs/PIPELINE.md` §5). Run
   `./scripts/check_matrix.py --routing` on the routed board.
5. **Diffs are polluted by CRLF churn.** Use `git diff -w` and `git status --porcelain`.
   Do not "fix" hundreds of files at once; line endings are handled by `.gitattributes`.
6. **Uncertainty is written down, not guessed silently.** Anything you cannot verify from the
   repo (external datasheets, vendor stock, a decision the author no longer remembers) must be
   tagged `⚠️ UNVERIFIED` or `🟡 BEST-GUESS` in the docs, per the convention in
   `docs/README.md` §2.
7. **Do not change layout, switch type, keycap spacing, or the matrix↔MCU pin map without
   asking.** Those are locked decisions (`docs/DECISIONS.md`) and each one has physical
   consequences (keycaps would collide, a row would be dead, etc.).

## 4. Local commands that work on this machine

Docker is **not** available from WSL, so KiBot / freerouting / gerbers only work in CI (or in
Windows Docker Desktop). Everything else runs locally.

```bash
# 0) Node lives in Windows (fnm). Use node.exe from WSL:
node.exe --version                      # v24.x

# 1) Regenerate PCB/plate/outlines/cases from config.yaml  (no docker needed)
./scripts/regen.sh                      # == node.exe node_modules/ergogen/src/cli.js ./ergogen/ --output ./ergogen/output --clear

# 2) Validate the electrical design against the config (fast, stdlib only)
./scripts/check_matrix.py               # matrix ↔ MCU pin map, dangling nets, duplicate pins
./scripts/check_matrix.py --routing     # additionally require routed copper + vias

# 3) Validate print files (watertight, normals, bbox)
./scripts/check_print_files.py
./.venv/Scripts/python.exe scripts/check_assembly.py   # wiring + parts fitting each other

# 4) Python (trimesh/cadquery/ezdxf) — the project venv, NOT system python
./.venv/Scripts/python.exe -c "import trimesh; print(trimesh.__version__)"
./.venv/Scripts/python.exe palmrest_and_tenting_creation/create_tenting_system.py

# 5) The configurator (local web app; run it from Windows, then open the printed URL)
node.exe configurator/server.mjs          # http://localhost:5173
node.exe configurator/lib/generate.mjs configurator/presets/sweepyway.json --out /tmp/x.yaml

# 6) Full 3D preview composition (needs the STL/GLB produced earlier)
./.venv/Scripts/python.exe fix_glb_scale.py --verbose
./.venv/Scripts/python.exe create_full_3d_visual.py
```

3D models in the PCB are referenced through `${PATH_TO_SWEEPYWAY_COMPONENT_MODELS}`. For any
local KiCad/KiBot run, set **both** that and `KICAD9_3DMODEL_DIR` (see `.env.example`).

```bash
# 6) Verify an external fact instead of guessing (datasheets, dimensions, vendor stock):
node.exe C:/a/d/dev_agents/tools/websearch/websearch.mjs search "kailh choc v2 plate cutout" --count 5
node.exe C:/a/d/dev_agents/tools/websearch/websearch.mjs fetch  <url> --max-chars 6000
```
Search works (Brave, `URIEL_PERSONAL_BRAVESEARCH_API_KEY` in the dev_agents `.env`). When a doc
claims a dimension and you verify it, put the number **and the source URL** in the doc and drop the
`⚠️ UNVERIFIED` marker.

For **ergogen semantics**, don't search — read `node_modules/ergogen/src/*.js` (it is the ground
truth) or check the Discord corpus if one has been exported (`docs/README.md` §3).

## 5. What to check before saying "done"

| Change | Must run |
|---|---|
| `config.yaml` / footprint edit | `scripts/regen.sh` && `scripts/check_matrix.py` |
| Anything touching outlines/cases | above + `check_print_files.py` + eyeball STL bbox |
| Anything touching kibot/CI | read `docs/PIPELINE.md` §5 first, then a CI run on a branch |
| Anything touching BOM/POS | `docs/BOM.md` quantities must still match the generated PCB footprint counts |

A quick way to count what the board actually contains:

```bash
./scripts/check_matrix.py --counts      # footprints per type per half
```

## 6. Known traps

- `ergogen/output/**` is gitignored but present locally — it is **generated**, always regenerate
  before diffing against expected output.
- `filtered-output/**` in the repo is a *download from CI*, not local build output. It can be
  older or newer than the config. Check file dates / the CI run number before trusting it.
- Undefined ergogen variables silently pass through as strings (e.g. `keycap_x_space`), which
  can produce `NaN` geometry instead of an error. Grep generated output for `NaN` after edits.
- The `kibot` GH action hardcodes `ergogen/output/pcbs/${board}.kicad_pcb`; it therefore
  exports the **unrouted** board even when asked for the routed one (`docs/PIPELINE.md` §5).
- KiCad exports GLB in mm but glTF expects m → `fix_glb_scale.py` exists for a reason.
- The workflow `paths:` filter does not include `.gitmodules`, so a submodule-pointer-only
  commit does not trigger a build.
- Ergogen zone overrides are subtle and easy to get wrong: `rows.<row>` / `columns.<col>.rows.<row>`
  are merged **as key properties directly** (no `key:` wrapper), `shift` accumulates row→row and
  `stagger`/`spread`/`splay` are only read from the first row and accumulate column→column. Full
  table in `docs/ERGOGEN-GUIDE.md` §4.7. Spike-test before designing around it.
- Outline `rectangle.size` is the **full** extent. Halving it silently produces 7 mm switch
  cutouts (this happened — bug B10). `scripts/check_matrix.py --plates` guards it.
- A *generated* config (from the configurator) is not the same as the repo's `config.yaml`: it
  auto-assigns pins and adds the right-half screws. Do not assume the two are interchangeable
  without diffing the points (`docs/CONFIGURATOR.md` §3).
